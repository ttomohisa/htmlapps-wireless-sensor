最大4台のスマートフォンをワイヤレスな動きセンサーとしてPCへ同時接続し、WebRTCで同期記録する Browser Kitty の単一HTMLツールです。実験プリセット、衝撃時間差、FFT、縦並び比較、記録後解析に加え、迷いにくいQR接続、長時間計測向けのバッテリー/負荷制御、マーカー、センサー位置、再読み込みできる計測セッション、単一HTMLレポートまでブラウザーだけで扱えます。

## 🚀 デモ

### [GitHub PagesでWireless Sensorを開く](https://ttomohisa.github.io/htmlapps-wireless-sensor/)

PC / タブレットとスマートフォンの両方で同じページを開いて使います。GitHub Pagesが配信するのは最初のHTMLだけです。WebRTCの接続情報はQRまたはコピー＆ペーストで端末間を直接受け渡しし、センサー値もP2Pで送信します。シグナリング、STUN、TURNサーバーは使いません。

[![Wireless Sensorの画面](assets/screenshot-ja.png)](https://ttomohisa.github.io/htmlapps-wireless-sensor/)

## 主な機能

- **実験プリセット** — **衝撃伝播 / 振動比較 / 傾き比較 / 回転比較 / 車・自転車 / エレベーター / 洗濯機・モーター / 自由計測** を用意。選ぶだけで計測モード、表示方法、時間幅、衝撃検出、推奨送信頻度をまとめて設定し、スマホの置き方と実験手順も表示します。
- **記録後解析ビュー** — 記録停止後に、測定時間・端末数・サンプル数・衝撃・同期精度、端末別の振動ピーク/RMS/主周波数、イベント周辺の拡大波形まで自動でまとめます。
- **マーカー / メモ** — 記録中に「モーターON」「ブレーキ」「机を叩いた」などのメモを共通時間軸へ追加し、解析画面・セッションJSON・HTMLレポート・CSVへ残せます。
- **センサー位置・配置** — センサー名とXYZ位置（cm）を登録できます。位置がある場合、衝撃イベントで端末間距離と見かけの伝播速度も表示します。
- **計測セッションの保存・再読み込み** — JSONを正式なセッションファイルとして保存し、v4〜v8の記録を後から開いて解析画面を復元できます。スマホの再接続は不要です。
- **単一HTML結果レポート** — 測定サマリー、センサー配置、振動/RMS/FFT、衝撃時間差、マーカー、簡易振動グラフを1つのHTMLへまとめて保存できます。
- **最大4台のスマホを同時計測** — 受信PCはスマホごとに独立したWebRTC接続を持ち、1台が切れても他の接続を継続します。
- **スマホをワイヤレスな動きセンサーに** — 加速度、重力込み加速度、回転速度、端末の向きをブラウザーから取得します。
- **シグナリングサーバーなしで接続** — WebRTCは `iceServers: []` で作成し、ICE候補収集が `complete` になったOffer / Answerだけを端末間で直接受け渡します。15秒以内に収集完了しない試行は、不完全なSDPを使わず破棄します。
- **両方向ともカメラQRが基本** — 受信側を選ぶとPCのOffer QRを自動生成し、スマホ側を選ぶとQRカメラを自動起動。Offer読取後はスマホがいったん待機し、PC側で返答QRカメラを起動してからAnswerを生成します。接続前にスマホ側ICEが失敗した場合はAnswer QRを自動再生成し、PCカメラは開いたまま読み取りを継続できます。ICE収集状態、ローカル/相手候補の種類、候補ペア成立状況も表示します。
- **普通のカメラで読みやすいQR** — 接続情報を低密度な複数QRへ分割し、読み取れたページ数をバーで表示。低解像度PCカメラを考慮して返答QRの自動切替もゆっくりにしています。スマホは背面カメラを優先し、PCではネイティブQR読み取りが使えない場合に内包済み `jsQR` へ自動フォールバックします。
- **個別・重ね合わせ・縦並び比較** — センサーを1台ずつ選ぶ従来表示と全センサー重ね合わせに加え、加速度など同じ信号を端末ごとのグラフとして上下に並べ、波形の違いを直接比較できます。
- **時計差を補正して同期記録** — 接続直後と定期的なPing/Pongから各スマホとPCの時計差・ドリフトを推定し、低RTTのサンプルを優先して共通時間軸へ補正します。同期精度の目安も端末ごとに表示します。
- **用途に合わせた計測モード** — **動き / 振動 / 傾き / 回転 / 自由表示** を切り替えられます。振動では直近2秒のRMS・ピーク・振動幅、回転では合成回転速度などを表示します。
- **衝撃イベントと端末間時間差** — 重力を除いた加速度がしきい値を超えた瞬間を自動検出し、時計同期後の時刻で同じ衝撃を端末間グループ化。最初の端末から何ms後に他端末へ届いたかを表示します。
- **FFT周波数分析** — 選択中端末の直近約4秒をローカル解析し、主な周波数・次のピーク・周波数分解能を表示します。X/Y/Zのうち変動が最も大きい軸を自動選択して解析します。
- **バッテリー / 負荷を抑えた長時間計測** — スマホ側は省電力 / 標準 / 高精度の送信設定に合わせて画面更新を間引き、DataChannelが詰まった場合は古いサンプルを待たず負荷保護します。画面維持（Wake Lock）はON/OFF可能です。受信PCもライブ値更新を最大約10fps、グラフを通常約30fps・縦並び約15fpsへ抑え、記録サンプル自体は落とさず描画だけ軽量化します。
- **単一HTML・日英UI** — QR関連ライブラリはビルド時にHTMLへ内包し、日本語 / 英語を同じHTMLで切り替えられます。

## すぐに使う

### Webで使う

1. 両方の端末で [Wireless Sensor](https://ttomohisa.github.io/htmlapps-wireless-sensor/) を開きます。
2. PCとスマホを同じWi-Fi / LANへ接続します。
3. PC / タブレットで **この端末で測定を見る** を選びます。接続QRは自動で作成されます。
4. スマホで **このスマホをセンサーにする** を選びます。QRカメラが自動で開くので、PCに表示されたQRを読み取ります。
5. Offerの読み取りが終わったら、PC側で **スマホの返答QRをカメラで読む** を先に押し、PCカメラ映像が表示された状態にします。
6. スマホ側で **PC側の準備ができた — 返答QRを作る** を押し、表示された返答QRをPCカメラへ向けます。接続前にスマホ側ICEが失敗した場合は返答QRが自動更新されるので、PCカメラはそのままにします。
7. WebRTC接続後、スマホで **センサーを開始** を押し、必要なセンサー権限を許可します。
8. さらにスマホを追加する場合は、PC側の **センサーを追加** を押して同じQR接続を繰り返します。最大4台まで同時接続できます。

インストールやアカウント登録は不要です。スマホのカメラ・モーションセンサー権限のため、HTTPSで公開したページからの利用を推奨します。

### 単一HTMLをビルドして使う

1. このリポジトリをダウンロードまたはクローンします。
2. Windows 10 / 11で `build-standalone.bat` をダブルクリックします。
3. 初回のみ、`dependencies.json` で固定された依存パッケージを取得します。
4. 生成された `dist/index.html` を開くか、任意の場所へコピーします。

Python、Node.js、ローカルWebサーバーは不要です。Windows標準のPowerShellと `tar.exe` を使用します。

## 使い方

### 受信側: PC / タブレット

1. **この端末で測定を見る** を選ぶと接続QRが自動生成されます。分割QRで1〜4台のスマホを接続します。追加時も **センサーを追加** を押すだけで新しいQR生成を開始し、既存センサーは維持されます。
2. **センサー位置・配置** で端末名を変更し、必要ならXYZ位置をcm単位で登録します。配置は受信側のセンサースロットごとに保持されます。
3. **実験プリセット** または **計測モード** を選び、個別・重ね合わせ・縦並び表示を使います。
4. **衝撃イベント**、時計同期後の時間差、**周波数分析 (FFT)** を確認しながら計測します。
5. 記録を開始すると、全センサーが補正済みの共通時間軸へ保存されます。
6. 記録中に意味のある出来事があれば、メモを入力して **現在時刻にマーカー** を押します。
7. 記録停止後は **測定結果** で、端末別指標・衝撃時間差・イベント周辺波形・マーカー・記録全体FFTを確認できます。
8. **CSV**、再読み込み可能な **セッションJSON**、自己完結の **HTMLレポート** を保存できます。
9. **過去の記録を開く** から保存済みセッションを読み込むと、スマホを再接続せず解析画面とレポートを再生成できます。

### 送信側: スマホ

1. **このスマホをセンサーにする** を選びます。QRカメラが自動で起動します。
2. カメラを再起動したい場合は **PCのQRをカメラで読む** を押します。利用できる場合は背面カメラを優先します。
3. ガイド枠いっぱいにQRを映します。複数ページは順不同で自動収集します。
4. 全ページが揃うとOfferを復元しますが、この時点ではAnswerやICE接続確認をまだ開始しません。
5. PC側で **スマホの返答QRをカメラで読む** を押し、カメラ映像が表示されたら、スマホ側の **PC側の準備ができた — 返答QRを作る** を押します。
6. 返答QRをPCカメラへ見せます。接続前にスマホ側ICEが先に失敗した場合は、返答QRを最大3回自動再生成します。PCカメラは開いたままで構いません。
7. 接続後、**センサーを開始** を押して権限を許可します。
8. 送信頻度は **省電力 / 標準 / 高精度** から選べます。これは送信の間引き設定であり、端末のセンサー取得頻度を保証するものではありません。省電力ではスマホ画面の数値更新も減らします。
9. **測定中は画面をオンに保つ** をOFFにするとバッテリーを節約できます。ただし画面消灯後にブラウザーがセンサーイベントを止める端末があるため、連続計測ではONを推奨します。

どちらかのカメラでQRを読めない場合のため、接続コードのコピー＆ペーストもフォールバックとして残しています。

## センサーデータ

Wireless Sensorはブラウザーの `devicemotion` / `deviceorientation` を利用します。主な記録項目は以下です。

- acceleration x / y / z
- 加速度の大きさ `√(x² + y² + z²)`
- acceleration including gravity x / y / z
- rotation rate alpha / beta / gamma
- orientation alpha / beta / gamma
- orientation absolute
- `DeviceMotionEvent.interval`
- センサーID / センサー名 / 端末ラベル
- 時計同期で補正した共通経過時間（複数端末比較用）
- パケット受信時刻基準の経過時間（診断・フォールバック用）
- 推定同期誤差、時計差、ドリフト量
- 実験プリセット、計測モード、振動値、回転速度の合成値
- 任意のセンサーXYZ位置（cm）
- 記録中に追加したマーカー / メモ（セッションJSONに保存、CSVでは最も近いサンプル行へ付与）
- 記録中に検出した衝撃イベント（session JSON v8）
- センサーごとの経過時間、センサー側タイムスタンプ、受信時刻
- シーケンス番号

セッションJSON v8には、センサー配置、衝撃イベント、マーカー、同期情報、全サンプルを保存し、後からWireless Sensorで再読み込みできます。

ブラウザーや端末が提供しない値はCSVでは空欄、JSONでは `null` として保存します。

## GitHub Pagesで公開する

このリポジトリには、依存ライブラリを内包した単一HTMLをビルドし、`dist/` をGitHub Pagesへ自動公開するワークフローが含まれています。

1. リポジトリ名を `htmlapps-wireless-sensor` としてGitHubへプッシュします。
2. **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
3. `main` へプッシュするか、Actions画面から **Deploy standalone app to GitHub Pages** を手動実行します。
4. ビルド成功後、`https://ttomohisa.github.io/htmlapps-wireless-sensor/` で公開されます。

`main` へのプッシュ時には、固定バージョンの依存パッケージからアプリを再生成し、単一HTMLを検証してから公開します。GitHub Pagesがまだ有効でない場合は、ビルドだけ成功させたうえで設定手順をWorkflow Summaryへ表示します。

## プライバシーと通信

Wireless Sensorは、シグナリング、STUN、TURNのインフラを意図的に使いません。

- WebRTCは `RTCPeerConnection({ iceServers: [] })` で作成します。
- Offer / AnswerはQRまたはコピー＆ペーストで端末間を直接受け渡します。
- センサー値はWebRTC DataChannelで接続相手へ直接送信します。
- 生の測定サンプルとマーカーは受信側ブラウザーのメモリに保持し、ユーザーが明示的にCSV・セッションJSON・HTMLレポートを保存したときだけファイルになります。言語・表示設定・センサー名/XYZ位置は、このブラウザーのlocalStorageにだけ保存されます。
- 生成HTMLは通常の実行時ネットワークAPIを抑止するため、`connect-src 'none'` を含むContent Security Policyを維持します。
- QR生成 / 読み取りライブラリはHTMLへ内包し、実行時CDNはありません。

GitHub Pages版では最初のHTML配信は発生します。ネットワークを完全に切って使う場合は `dist/index.html` をローカルで開けますが、`file://` ではブラウザーによってカメラやセンサー権限がより厳しくなるため、接続コードの手動受け渡しが必要になる場合があります。

## 制限事項

- **基本的に同じWi-Fi / LANでの利用を想定**しています。STUN / TURNを使わないため、異なるネットワークやNAT越しの汎用的な接続は対象外です。
- 会社・学校・ゲストWi-Fi、VPN、ファイアウォール、Client Isolation / AP Isolationなどにより、同じWi-Fi表示でも端末間通信が遮断される場合があります。
- 接続QR / 返答QRはICE候補収集完了後にだけ生成します。スマホはPC側の返答QRスキャナーが開くまでAnswer生成を待機します。接続前のスマホ側ICEが失敗した場合は最大3回まで新しいAnswerを自動再生成し、ICE候補収集自体が15秒以内に完了しない試行は破棄します。接続失敗時は画面のICE診断（候補数・候補種別・ICE状態・候補ペア）も確認してください。
- ブラウザーのセンサー値は校正済みの専用計測器の代替ではありません。精度、利用できる値、取得頻度は端末・OS・ブラウザーで異なります。
- `DeviceMotionEvent` の軸の扱いはブラウザーエンジン間で異なる場合があります。異なるブラウザーを混在させる場合は軸方向を事前確認するか、振動RMS/ピークなど方向に依存しにくい指標を優先してください。
- iPhone / iPadなどでは、モーションセンサー利用時にユーザー操作から明示的な権限許可が必要です。
- スマホをバックグラウンド化したり画面ロックしたりすると、ブラウザーのセンサーイベントが止まる場合があります。画面維持をOFFにする省電力運用では特に注意してください。
- 長時間の記録は保存するまで受信側メモリに保持します。複数台ではサンプル数も増えるため、必要に応じて区切って保存してください。大きな保存済みセッションの再読み込み時も受信側メモリを使用します。
- 時計同期はWebRTC DataChannel上のPing/Pongから推定する簡易方式です。低RTTサンプルを優先し時計差と長時間のドリフトを補正しますが、ネットワーク経路の非対称遅延やOS/ブラウザーのタイマー特性までは保証できません。科学計測用のPTP/GNSS同期の代替ではありません。
- v1.0.0では同時接続は最大4台です。GPS、磁気、マイク計測、QR接続以外のカメラ計測は対象外です。
- 衝撃検出はブラウザーから得られる加速度サンプルを使う簡易検出です。しきい値・取得頻度・端末固定方法によって検出時刻は変わります。
- FFTの上限周波数は実測サンプルレートの約半分です。標準30Hz前後なら解析できる上限は約15Hzで、高い周波数の振動解析には向きません。
